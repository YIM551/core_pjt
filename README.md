# AI 코어 프로젝트 3회차 · PJT01 라즈베리파이 기기 연동

라즈베리파이 5의 카메라 영상을 PC 대시보드로 중계하고, 영상과 사용자 질문을 바탕으로 선택한 `move`, `describe`, `ask`를 실행한다. 기기 탭에서 이동 방향은 OLED와 LED로 출력한다. 기존 2회차 API(A1~A5)와 도구 선택 규칙(R1~R5)을 유지하며, 카메라·LED·OLED 중계 API(A6~A8)를 추가했다.

**실제 라즈베리파이를 연결한 최종 API 검증 결과는 118/118 PASS다.**

## 구성과 동작 흐름

| 구성 | 역할 |
| --- | --- |
| 라즈베리파이 5 · TCP 8080 | Picamera2로 카메라 영상을 640×480 MJPEG로 제공한다. 기본값은 15 FPS이며, 제출 검증은 10 FPS에서 수행했다. GPIO LED와 SPI OLED를 제어한다. |
| Windows PC · TCP 8000 | FastAPI로 대시보드를 제공하고 MJPEG를 재인코딩 없이 중계한다. YOLO, VLM, PC LLM(Qwen3-4B)을 실행하고 방향을 LED 핀과 OLED 문자열로 변환한다. |
| 브라우저 | 기기 IP를 등록하고 영상·스냅샷을 표시한다. MediaPipe로 손 방향을 인식하며, 탭별 대화 기록을 요청에 담아 보낸다. |

연동 탭에서 라즈베리파이 IP를 등록한 뒤 기기 탭에서 질문을 전송하면, 현재 영상 프레임을 스냅샷으로 사용한다. YOLO 객체 검출, VLM 장면 설명, MediaPipe 손 방향 결과를 질문과 함께 PC LLM에 전달한다.

| 도구 | 기기 탭 동작 | 확인용 입력 |
| --- | --- | --- |
| `describe` | 장면 설명을 표시한다. | `앞에 뭐가 있어?` |
| `move` | OLED에 방향을 표시하고, 좌우 이동일 때만 해당 LED를 3회 점멸시킨다. 연속 이동은 첫 동작과 `then`의 동작을 차례로 출력한다. | `오른쪽 2칸 가고 위로 1칸` → OLED `RIGHT → UP`, 오른쪽 LED만 점멸 |
| `ask` | 방향을 되묻고 후속 답변을 받는다. 되묻는 동안에는 기기 출력을 보내지 않는다. | `저쪽으로 가` → 방향을 묻는 답변 → `왼쪽` |

| 방향 | OLED | LED(BCM) |
| --- | --- | --- |
| 왼쪽 | `LEFT` | GPIO 27 |
| 오른쪽 | `RIGHT` | GPIO 17 |
| 위 | `UP` | 점멸 없음 |
| 아래 | `DOWN` | 점멸 없음 |

이동 명령에 포함된 칸 수는 도구 인자에 유지한다. 기기 탭의 답변은 “오른쪽으로 이동합니다.”처럼 방향만 표시하며, 로컬 PC 탭은 기존 칸 수 안내를 사용한다.

## 실행 방법

PC는 Python 3.12와 기존 `.venv`를 사용한다. 프로젝트 루트에 `yolo11n.pt`를 두고, `models/`에 Qwen2.5-VL과 mmproj, Qwen3-4B, `gesture_recognizer.task`를 둔다. 모델 가중치는 실행 환경에서 별도로 준비한다. 라즈베리파이는 Picamera2와 gpiozero를 사용할 수 있는 Python 환경, `luma.oled`와 Pillow, SPI가 활성화된 상태가 필요하다. PC에서 라즈베리파이의 TCP 8080에 접속할 수 있어야 한다.


PC 환경을 새로 만드는 경우 프로젝트 루트에서 다음을 실행한 뒤, [환경 준비 명령](source/3회차_day1/설치_명령어_기기.sh)의 모델 배치 안내를 따른다.

```powershell
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
```

1. PC PowerShell에서 프로젝트 루트를 열고 기기 서버 파일을 복사한다. IP와 계정은 실제 환경에 맞게 바꾼다.

   ```powershell
   scp .\source\3회차_day1\page45_기기서버_D1_D3\camera_server.py rp5@192.168.110.141:~/
   ```

2. 수동 실행으로 확인하려면 라즈베리파이 SSH 터미널에서 기기 서버를 실행하고 창을 열어 둔다. 부팅 자동 실행을 사용할 때는 [systemd 설치 절차](source/3회차_day1/심화_F105_F106/README.md)를 따른다. 카메라 점유 충돌을 피하려면 한 방식으로만 실행한다.

   ```bash
   ~/venv/bin/python3 ~/camera_server.py --fps 10
   ```

3. PC의 프로젝트 루트에서 기기 연동 서버를 실행한다. 기준선 서버를 실행 중이면 먼저 종료해 PC의 8000 포트를 비운다.

   ```powershell
   & .\.venv\Scripts\python.exe .\source\3회차_day1\page61_기기연동\대시보드_기기연동.py
   ```

4. 브라우저에서 [대시보드](http://127.0.0.1:8000)를 열고, 연동 탭에서 라즈베리파이 IP를 등록한 뒤 **1번 기기**를 선택한다. PJT01은 텍스트 질문을 PC LLM으로 처리하며, 음성 입력은 PJT02에서 추가된다.

### R6·R7 · 기기 장애 격리와 탭별 대화

브라우저에서 같은 대시보드 세션을 유지하며 기기 쪽 연결을 끊었다가 복구했다. 실제 라즈베리파이의 영상과 기기 API를 테스트용 로컬 중계로 연결해 해당 경로만 차단했다. 로컬 PC 탭에는 샘플 이미지로 만든 테스트용 카메라 스트림을 입력했고, YOLO·VLM·LLM은 실제 PC 서버에서 실행했다.

| 검증 | 확인 결과 |
| --- | --- |
| **R6 · 기기 연결 오류 격리** | 기기 탭은 영상 끊김을 표시하고 카메라 중계는 HTTP 502를 반환했다. 같은 장애 중에도 로컬 PC 탭은 ‘저쪽으로 6칸 가’의 이미지 분석과 되묻기를 완료했다. ‘오른쪽’이라는 후속 입력에는 `move(right, 6)`을 반환했다. |
| **R6·R7 · 재연결 후 진행 중인 대화 유지** | 기기 탭에서 ‘저쪽으로 3칸 가’로 되묻기 상태를 만든 뒤 연결을 끊었다. 복구 후 같은 탭에서 기존 질문과 답변이 남아 있었고, ‘왼쪽’만 입력해 `move(left, 3)`을 받았다. 기기 OLED·LED API도 HTTP 200으로 응답했다. |
| **R7 · 탭별 대화 분리** | 두 탭의 화면에는 각각 자기 질문만 표시됐다. 두 후속 API 요청의 `history`에는 각 탭의 최초 질문과 되묻기 응답만 있었다. 로컬 PC 탭은 6칸, 기기 탭은 3칸을 각각 유지했다. |

이 검증 범위는 같은 페이지 안에서의 탭 전환과 기기 재연결이다.

## F105 · 카메라 스트림 안정화

640×480, 10 FPS로 설정했다. PC 중계는 프레임 데이터가 10초 동안 도착하지 않으면 연결을 종료하고, 브라우저는 3초 뒤 다시 연결을 시도한다.

| 시험 | 확인 결과 |
| --- | --- |
| 실제 카메라 프레임으로 YOLO·VLM 처리 | 두 요청 모두 HTTP 200. PC 중계에서 약 4.7초간 47프레임을 수신했다(평균 9.9 FPS, 최대 프레임 간격 0.14초). |
| 브라우저 기기 탭에서 질문 전송 | VLM 처리 중 표시 FPS가 일시적으로 1.3까지 내려갔지만 영상 연결을 유지했고, 분석과 최종 답변을 완료했다. |
| 영상 데이터만 중단 후 복구 | 테스트용 로컬 중계에서 라즈베리파이의 프레임 전달만 일시 중단했다. 대시보드에 ‘연결 끊김 — 3초 뒤 다시 연결’이 표시됐으며, 전달을 재개하자 새로고침 없이 같은 탭에서 영상이 복구됐다(표시 10.2 FPS). |

## F106 · 부팅 자동 실행과 장애 복구

[`camera-stream.service`](source/3회차_day1/심화_F105_F106/camera-stream.service)는 라즈베리파이 부팅 시 사용자 가상환경에서 카메라 서버를 10 FPS로 시작한다. `Restart=on-failure`와 `RestartSec=3`으로 비정상 종료 후 재시작하도록 설정했다.

| 시험 | 확인 결과 |
| --- | --- |
| 서비스 등록 | `systemctl is-enabled` → `enabled`, `systemctl is-active` → `active` |
| 라즈베리파이 재부팅 | 수동으로 서버를 실행하기 전에 `active` 확인. 이번 부팅의 저널에서 부팅 약 20초 뒤 카메라와 OLED 초기화, 640×480·10 FPS 스트림 시작을 확인했다. PC에서 직접 스트림과 중계 영상 프레임도 수신했다. |
| 비정상 종료 후 복구 | 메인 프로세스를 강제 종료한 뒤 서비스가 다시 `active`가 됐다. `MainPID`는 1372 → 1812, `NRestarts`는 0 → 1로 바뀌었다. 라즈베리파이 직접 스트림과 PC 중계가 모두 HTTP 200을 반환했으며 PC 중계에서 약 1초간 JPEG 프레임 10개를 수신했다. |

## 해결한 문제

- **기기 탭 영상 연결 실패:** 기준선 서버에는 `/api/camera-stream`이 없어 기기 중계 요청이 404였다. PC 서버를 기기 연동 버전으로 바꾼 뒤 실제 라즈베리파이의 영상 중계를 검증했다.
- **OLED의 상하 방향 지원:** A8의 방향 매핑과 검증 조건을 명세서의 네 방향에 맞췄다. A7은 좌우만 허용하며, 검증 스크립트는 연속 이동에 대해 `RIGHT → UP`을 확인한다.
- **연결어 없는 연속 이동:** `왼쪽으로 3칸 아래로 2칸`처럼 방향과 칸 수를 연달아 입력했을 때 두 동작을 분리하도록 수정했다. 실제 기기에서는 OLED 요청이 `LEFT → DOWN`, LED 요청은 왼쪽 이동에만 전달됐다.
- **라즈베리파이 8080 연결 거부:** 기기 서버가 8080에서 응답하지 않는 상태를 확인했다. 라즈베리파이에서 `camera_server.py`를 실행한 뒤 전체 실기기 검증을 완료했다.
