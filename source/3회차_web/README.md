# 3회차 웹 대시보드 화면 (완성본)

3회차 1 ~ 3일차 PC 서버가 함께 쓰는 프런트다. **수정하지 않는다** ― 서버만 만든다.
2회차 화면에 **연동 탭 · 기기 탭**(라즈베리파이 영상 · OLED · LED 출력 · 음성 자동 입력 · 연결 상태 줄)이 더해졌다.

| 파일 / 폴더 | 내용 |
|---|---|
| `index.html` | 대시보드 화면 (연동 · 대시보드(로컬 PC · 기기) · 시뮬레이터 탭) |
| `mediapipe/` | 브라우저 제스처 인식 번들 (2회차와 같은 파일). 모델 `gesture_recognizer.task` 는 서버가 `models\` 에서 내준다 |

## 여는 법

html 파일을 더블클릭하면 **동작하지 않는다**. 실습 서버를 띄운 뒤 브라우저에서 <http://127.0.0.1:8000> 으로 연다.

| 서버 | 되는 것 |
|---|---|
| `3회차_day1/page23_기준선_검증` | 2회차와 같다 ― 로컬 PC 탭 · 시뮬레이터 (기기 탭은 영상 오류가 정상) |
| `3회차_day1/page53_카메라_중계` | + 기기 탭 라즈베리파이 영상 (A6) |
| `3회차_day1/page61_기기연동` | + move → OLED · LED (A7 · A8), 기기 탭 답변 칸 수 없이 (R10) |
| `3회차_day2/page41_음성중계_A9` | + PTT 음성 → 입력창 자동 입력 · 전송 (A9) |
| `3회차_day2/page62_음성경로_통합` | + 기기 탭 질문은 기기 LLM 이 도구 선택 (D5 · R9) ― 완성 |

앞 단계 서버에서는 아직 없는 API 를 화면이 부르면 그 칸만 오류가 난다 (예: 1일차 서버의 '음성 ● 끊김').
로컬 PC 탭은 어느 단계에서나 2회차와 똑같이 동작한다.

## 화면이 서버에 보내는 것

| 기기 탭 동작 | 요청 |
|---|---|
| 영상 | `GET /api/camera-stream?ip=` (A6) ― 끊기면 3초 뒤 다시 연결 |
| [전송] (타이핑) | `POST /api/llm-answer` + `source: "device"`, `ip` (A5) |
| PTT 음성 자동 전송 | 1초마다 `GET /api/voice-poll?ip=` (A9) → seq 가 커지면 `source: "voice"`, `ip` (A5) |
| move 출력 | 이동마다(args 다음 then, 2초 간격) `POST /api/oled-display` (A8), 좌우만 `POST /api/robot-signal` (A7) |
| history | 기기 탭마다 따로 보관 ― ask 면 남기고, 최종 답이면 비운다. 오류(502) 때는 유지한다 (R6 · R7) |

API · 규칙 번호는 명세서(`16-C-3-01 ~ 03`)의 'API 및 규칙 명세' 표와 같다.
