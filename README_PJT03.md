# AI 코어 프로젝트 3회차 · PJT01 라즈베리파이 기기 연동

라즈베리파이 5의 카메라 영상을 PC 대시보드로 중계하고, 영상과 사용자 질문을 바탕으로 선택한 `move`, `describe`, `ask`를 실행한다. 기기 탭에서 이동 방향은 OLED와 LED로 출력한다. 기존 2회차 API(A1~A5)와 도구 선택 규칙(R1~R5)을 유지하며, 카메라·LED·OLED 중계 API(A6~A8)를 추가했다.

**실제 라즈베리파이를 연결한 최종 API 검증 결과는 116/116 PASS다.**

## 구성과 동작 흐름

| 구성 | 역할 |
| --- | --- |
| 라즈베리파이 5 · TCP 8080 | Picamera2로 카메라 영상을 640×480, 설정 15 FPS의 MJPEG로 제공한다. GPIO LED와 SPI OLED를 제어한다. |
| Windows PC · TCP 8000 | FastAPI로 대시보드를 제공하고 MJPEG를 재인코딩 없이 중계한다. YOLO, VLM, PC LLM(Qwen3-4B)을 실행하고 방향을 LED 핀과 OLED 문자열로 변환한다. |
| 브라우저 | 기기 IP를 등록하고 영상·스냅샷을 표시한다. MediaPipe로 손 방향을 인식하며, 탭별 대화 기록을 요청에 담아 보낸다. |

연동 탭에서 라즈베리파이 IP를 등록한 뒤 기기 탭에서 질문을 전송하면, 현재 영상 프레임을 스냅샷으로 사용한다. YOLO 객체 검출, VLM 장면 설명, MediaPipe 손 방향 결과를 질문과 함께 PC LLM에 전달한다.

| 도구 | 기기 탭 동작 | 확인용 입력 |
| --- | --- | --- |
| `describe` | 장면 설명을 표시한다. | `앞에 뭐가 있어?` |
| `move` | OLED에 방향을 표시하고, 좌우 이동일 때만 해당 LED를 3회 점멸시킨다. 연속 이동은 첫 동작과 `then`의 동작을 차례로 출력한다. | `오른쪽 2칸 가고 위로 1칸` → OLED `RIGHT → UP`, 오른쪽 LED만 점멸 |
| `ask` | 방향을 되묻고 후속 답변을 받는다. 되묻는 동안에는 기기 출력을 보내지 않는다. | `저쪽으로 가` → 방향을 묻는 답변 → `왼쪽` |

| 방향 | OLED | LED(BCM) |
| --- | --- | --- |
| 왼쪽 | `LEFT` | GPIO 27 |
| 오른쪽 | `RIGHT` | GPIO 17 |
| 위 | `UP` | 점멸 없음 |
| 아래 | `DOWN` | 점멸 없음 |

이동 명령에 포함된 칸 수는 도구 인자에 유지한다. 기기 탭의 답변은 “오른쪽으로 이동합니다.”처럼 방향만 표시하며, 로컬 PC 탭은 기존 칸 수 안내를 사용한다.

## 실행 방법

PC는 Python 3.12와 기존 `.venv`를 사용한다. 프로젝트 루트에 `yolo11n.pt`를 두고, `models/`에 Qwen2.5-VL과 mmproj, Qwen3-4B, `gesture_recognizer.task`를 둔다. 라즈베리파이는 Picamera2와 gpiozero를 사용할 수 있는 Python 환경, `luma.oled`와 Pillow, SPI가 활성화된 상태가 필요하다. PC에서 라즈베리파이의 TCP 8080에 접속할 수 있어야 한다.

1. PC PowerShell에서 프로젝트 루트를 열고 기기 서버 파일을 복사한다. IP와 계정은 실제 환경에 맞게 바꾼다.

   ```powershell
   scp .\source\3회차_day1\page45_기기서버_D1_D3\camera_server.py rp5@192.168.110.141:~/
   ```

2. 라즈베리파이 SSH 터미널에서 기기 서버를 실행하고 창을 열어 둔다.

   ```bash
   ~/venv/bin/python3 ~/camera_server.py
   ```

3. PC의 프로젝트 루트에서 기기 연동 서버를 실행한다. 기준선 서버를 실행 중이면 먼저 종료해 PC의 8000 포트를 비운다.

   ```powershell
   & .\.venv\Scripts\python.exe .\source\3회차_day1\page61_기기연동\대시보드_기기연동.py
   ```

4. 브라우저에서 [대시보드](http://127.0.0.1:8000)를 열고, 연동 탭에서 라즈베리파이 IP를 등록한 뒤 **1번 기기**를 선택한다. PJT01은 텍스트 질문을 PC LLM으로 처리하며, 음성 입력은 PJT02에서 추가된다.

## API 검증 결과

2026년 11월 18일, PC 기기 연동 서버와 라즈베리파이(`192.168.110.141:8080`)를 실행한 상태에서 검증했다. 아래 명령은 별도의 PC PowerShell 창에서 프로젝트 루트를 기준으로 실행한다.

```powershell
& .\.venv\Scripts\python.exe .\source\3회차_day1\page71_API_검증\API_검증.py --quick
& .\.venv\Scripts\python.exe .\source\3회차_day1\page71_API_검증\API_검증.py --device 192.168.110.141
```

`--quick`은 화면·정적 파일과 400·502 오류 처리를 검사한다. `--device`는 해당 검사에 모델 추론과 실제 기기 검증을 더하며, 실행 중 LED와 OLED를 제어한다.

```text
A1 1/1  A2 2/2  A3 3/3  A4 3/3  A5 21/21  A6 3/3  A7 5/5  A8 3/3
D1 1/1  D2 2/2  D3 2/2  F104 1/1
R1 13/13  R10 8/8  R2 13/13  R3 5/5  R4 13/13  R5 2/2  R8 11/11
개선2 1/1  개선4 2/2  개선5 1/1
전체 116/116 PASS
```

| 검증 대상 | 실행에서 확인한 결과 |
| --- | --- |
| 기존 기능 | 정적 파일, YOLO·VLM 추론, `move / describe / ask`, 되묻기 후 방향 이어받기 통과 |
| 기기 API 및 PC 중계 | D1 직접 스트림과 A6 중계에서 MJPEG 프레임 수신. D2·D3 직접 호출 및 A7·A8 중계 응답 통과 |
| 방향 출력 | 좌우 LED 요청 성공. OLED 네 방향 요청, 위쪽 이동 `UP`, 연속 이동 `RIGHT → UP` 통과 |
| 오류 처리 및 답변 | 잘못된 요청은 400, 접근할 수 없는 기기는 502. 기기 탭 이동·되묻기 답변에서 칸 수 생략 확인 |

기준선 서버의 `--quick` 실행은 9/9 PASS였다. 별도 기준선 전체 실행의 80/80 PASS는 [배포된 기준선 실행 기록](source/3회차_day1/page23_기준선_검증/실행결과.txt)에서 확인할 수 있다. 이번 실기기 실행에서는 기존 항목도 함께 재검증했다.

### 통합 확인 범위

자동 검증으로 영상 프레임 수신, 실제 장치 서버 응답, 방향별 출력 요청 순서를 확인했다. 실물 LED 점멸과 OLED 글자 표시, 브라우저의 영상·스냅샷 표시 여부는 화면 및 장치 관찰로 확인한다. 기기 단절 시 로컬 PC 탭의 독립 동작(R6)과 브라우저의 탭별 대화 기록 유지·분리(R7)도 브라우저에서 별도로 확인하는 항목이다.

## 해결한 문제

- **기기 탭 영상 연결 실패:** 기준선 서버에는 `/api/camera-stream`이 없어 기기 중계 요청이 404였다. PC 서버를 기기 연동 버전으로 바꾼 뒤 실제 라즈베리파이의 영상 중계를 검증했다.
- **OLED의 상하 방향 지원:** A8의 방향 매핑과 검증 조건을 명세서의 네 방향에 맞췄다. A7은 좌우만 허용하며, 검증 스크립트는 연속 이동에 대해 `RIGHT → UP`을 확인한다.
- **라즈베리파이 8080 연결 거부:** 기기 서버가 8080에서 응답하지 않는 상태를 확인했다. 라즈베리파이에서 `camera_server.py`를 실행한 뒤 전체 실기기 검증을 완료했다.
