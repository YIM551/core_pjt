# Furniture 학습 모델 대시보드 통합 검증

서버: http://127.0.0.1:8003

실행: 프로젝트 루트에서 `powershell -ExecutionPolicy Bypass -File scripts/start_furniture_dashboard.ps1`

재검증: 서버 실행 후 `node scripts/furniture_dashboard_validate.mjs`

`best.pt`를 `CORE_YOLO_MODEL`로 지정해 기존 대시보드에 연결했다. 기본 COCO 설정은 변경하지 않고 Furniture 전용 실행 스크립트를 추가했다. 모델 SHA-256, 입력 원본 및 캡처 해시, 실제 HTTP 응답과 LLM 요청 본문은 `validation.json`에 있다.

고정 valid 매니페스트에서 클래스별 첫 이미지를 선택했다. 예측 결과에 따른 이미지 교체는 하지 않았고 test는 사용하지 않았다. 각 사진은 실제 대시보드의 이미지 선택으로 입력했다. fetch 관찰 코드는 입력 바이트만 기록하며 모델 응답을 변경하지 않는다.

| 입력 | YOLO(conf=0.25) | VLM | LLM 최종 답변 |
|---|---|---|---|
| 소파 | Sofa 1개, 0.968 | 거실에 큰 소파가 있습니다, 장애물 없음. | 1개의 소파가 있습니다. |
| 의자 | Chair 1개, 0.991 | 방 안에 의자 하나가 놓여 있다, 장애물 없음. | 의자 1개가 방에 있습니다. |
| 테이블 | Sofa 1개 0.676 + Table 1개 0.526 | 테이블 위에 체크무늬 천이 깔려 있다, 장애물 없음. | 소파 1개, 테이블 1개가 보여요. |

세 사례 모두 HTTP 200, 동일 캡처의 YOLO/VLM 전달, YOLO 개수 요약과 VLM 설명의 LLM 전달, describe 도구, 한국어 응답, 브라우저 오류 없음 검사를 통과했다. 화면의 좌표 포함 상세 YOLO 표시와 LLM의 개수 요약은 의도적으로 다른 형식이다.

연결 정상과 인식 정확도를 구분해야 한다. 테이블 이미지의 단일 대상 위에 Sofa와 Table 박스가 겹쳤으며, 원본 주석은 Table 1개다. 이미지도 육안으로 확인했다. 이 경우 LLM은 잘못된 YOLO 개수까지 반영했다. 따라서 전체 세 클래스 인식이 정확하다고 판정하지 않는다. 소파·의자는 주석 개수와 일치하고 테이블은 불일치한다. VLM의 장애물 판단 역시 안전성의 검증 근거가 아니다.

후속 작업: F206의 모델 불일치 표시, 겹치는 서로 다른 클래스 박스 처리 기준 검토, 테이블/소파 혼동 사례 추가 검수. 임계값을 올려 정답을 숨기는 방식으로 이번 결과를 수정하지 않았다.

기존 제출물·검증 기록은 보존했으며 이번 결과는 별도 디렉터리에 저장했다. 3장의 연결 점검은 일반화 성능 평가를 대신하지 않는다.
