# VLM 해상도·출력 토큰 비교 및 적용

캐시를 사용하지 않는 새 추론을 측정했다. 224/336/448px × 40/60토큰 18회, 392/420px × 40/60토큰 12회, 추가 valid 이미지의 기준/후보 확인 18회, 최종 정책의 6장 전후 비교 12회로 총 60회다. 워밍업은 제외했다. 원본 이미지 6장만 사용했으므로 60개의 독립 이미지 실험은 아니다. test 87장은 사용하지 않았다.

프롬프트·temperature=0·한국어/40자/장애물 표기 검사·규격 재시도 정책은 유지했다. 모델 로딩은 시간에서 제외하고, 앱 결과 캐시를 우회하며 매 추론 전 model.reset()을 호출했다. 크기·토큰 조건은 고정 시드로 섞어 순서 영향을 줄였다. 실패·재시도까지 최종 응답 시간을 측정했다. 원문·토큰 사용량·finish_reason·재시도는 각 JSON에 보존했다.

| 설정 | 관찰 | 결정 |
|---|---|---|
| 224px | 빠르지만 의자 배경과 테이블 천 설명 오류 | 제외 |
| 336px | 의자·소파에 근거 없는 화장실 설명 | 제외 |
| 392px | 소파에 별도 베개가 있다는 설명 | 기본 설정 제외 |
| 420px | 첫 세 이미지는 양호, 추가 책상에서 규격 실패·재시도로 느려짐 | 모든 이미지에 일괄 적용하지 않음 |
| 448px | 기존 기준 | 테이블·불확실한 장면에 유지 |
| 40토큰 | 보통의 짧은 출력은 조기 종료하므로 상한 감소 효과가 작고, 책상 재시도도 남음 | 60토큰 유지 |

적용 정책: YOLO가 검출한 모든 물체가 Chair/Sofa/couch이고 각 confidence가 0.8 이상이면 420px, 테이블·다른 클래스·혼동·미검출·YOLO 오류이면 448px. 높은 confidence가 실제 정답을 보장하는 것은 아니며 이 분기는 품질 보장을 대신하지 않는다. YOLO의 추가 확인 시간도 최종 정책 시간에 포함했다. 원시 검출 및 F206 동작은 그대로 유지한다.

동일 이미지별 기준과 최종 정책을 새로 비교한 평균은 **6.223초 → 5.393초, 13.34% 단축**이었다. 상세한 이미지별 수치와 텍스트는 comparison.json, 원본 측정은 policy_validation.json에 있다. 앞 단계와 실행 순서·모델 상태가 다르므로 이전 7초대 수치에 이 비율을 단순 누적하지 않는다. 캐시 적중으로 얻은 결과가 아니다.

품질 평가는 소스 이미지를 육안 확인하고 출력 문장을 대조했다. 클래스 이름 포함 여부와 형식 통과는 1차 검사이며 사실성 정답 판정이 아니다. 기준 모델이 추가 책상에서 쓰는 불명확한 단어 '쇼트'는 기존 오류로 남아 있다. 최종 정책은 해당 이미지를 기준 448px와 같은 설명으로 유지하며 오류 자체를 해결하지 않는다. 장애물 문구는 모델 인용이며 실제 안전 판정이 아니다.

현재 서버는 http://127.0.0.1:8003 이다. /api/health의 vlm_settings와 VLM 응답의 max_side/max_tokens/cache_hit로 적용 설정을 확인할 수 있다. 동일 이미지 캐시 키에도 실제 선택 해상도를 포함한다. 기본값은 420px·60토큰·adaptive 활성화·detail448px다.

배포 후 실제 대시보드에서 소파·의자420px, 테이블448px를 확인했고 세 건 모두 캐시 미적중이었다. F206의 중복 후보 경고와 YOLO/VLM→최종 답변 연결도 유지됐다. 첫 소파 전송은 모델 로딩을 포함해 16.133초였으며 의자6.826초·테이블7.948초는 UI·MediaPipe 비용도 포함한다. 이 수치를 앞의 통제된 warm VLM 비교와 혼합하지 않는다. 적용 검증은 deployment_verification.json, 화면과 요청·응답은 browser/에 있다.

이전 설정으로 복원하려면 서버 시작 전에 CORE_VLM_MAX_SIDE=448, CORE_VLM_MAX_TOKENS=60, CORE_VLM_ADAPTIVE=0을 지정한다. 고정 설정 비교도 동일한 환경변수를 사용한다. 설정 변경 후에는 서버를 재시작한다.

재현 스크립트: scripts/benchmark_vlm_settings.py(screen/refine/confirm), scripts/validate_vlm_policy.py(최종 정책), scripts/summarize_vlm_study.py(집계). 측정 결과는 덮어쓰므로 기존 결과를 보존하려면 디렉터리를 복사한 뒤 재실행한다.
